# Justificativa da escolha das tecnologias

Texto pronto para o capítulo de desenvolvimento da monografia. As versões citadas são as de [architecture.md](../architecture.md). Os parágrafos podem ser colados na ordem e ajustados à formatação do trabalho.

---

Na concepção inicial do sistema, descrita no projeto do trabalho, a camada de servidor seria desenvolvida com o framework Laravel, da linguagem PHP. Durante a fase de especificação, essa decisão foi revista em favor do NestJS, framework para Node.js escrito em TypeScript, em sua versão 12, executado sobre o Node.js 22. O principal motivo foi a unificação da linguagem: o Nivela é composto por três aplicações, a API, o painel web destinado a professores e administradores e o aplicativo móvel destinado aos alunos, e a adoção do TypeScript em todas elas permitiu organizá-las em um único repositório (monorepo) gerenciado por npm workspaces, com um só conjunto de dependências, uma só configuração de verificação de tipos e uma só esteira de integração contínua. Essa unificação tornou possível compartilhar código entre as camadas, em especial os tipos das respostas da API, mantidos em um pacote próprio que é consumido pelos dois clientes, de modo que uma alteração no formato de um dado é detectada em tempo de compilação, e não apenas durante o uso. Soma-se a isso o fato de o NestJS impor uma organização modular por funcionalidade, com injeção de dependências, validação declarativa de entradas e separação clara entre controladores e serviços, padrão que o autor já utilizava no backend desenvolvido durante o estágio, o que reduziu o tempo de aprendizado e favoreceu a consistência da estrutura do código. O ecossistema de testes do Node.js, com Jest e supertest na API, Vitest e Testing Library no painel e jest-expo no aplicativo, também permitiu cobrir com testes automatizados as regras de negócio mais sensíveis, como a concessão de moedas, o resgate de prêmios e o desbloqueio de capítulos, utilizando a mesma linguagem e ferramentas semelhantes nas três aplicações.

Para a persistência dos dados, optou-se pelo PostgreSQL 17, executado em contêiner Docker durante o desenvolvimento, e pelo Prisma 7, com o adaptador `@prisma/adapter-pg`, como camada de acesso. O banco relacional atende diretamente às necessidades do domínio: as operações que envolvem moedas e resgates exigem transações atômicas, bloqueio de linhas (`SELECT … FOR UPDATE`) e índices únicos parciais, que garantem no próprio banco que uma recompensa seja concedida uma única vez por questão, plano ou resgate, mesmo diante de requisições simultâneas. O Prisma contribui com um esquema declarativo, migrações versionadas e um cliente totalmente tipado, que se integra ao restante do código em TypeScript e torna o modelo de dados uma fonte única de verdade, da qual o diagrama entidade-relacionamento do trabalho foi conferido. A versão 7 foi escolhida por ser a estável mais recente no período do desenvolvimento, estando a versão 8 ainda em fase de candidata a lançamento.

O painel web foi construído com React 19, Vite e Material UI, com roteamento por React Router, formulários com react-hook-form e zod e gráficos com Recharts. O React foi escolhido pela maturidade do ecossistema, pela disponibilidade de componentes prontos para interfaces administrativas, como tabelas, formulários e diálogos, e pelo fato de compartilhar o modelo de componentes com o aplicativo móvel, o que permitiu reaproveitar conhecimento e convenções entre as duas interfaces, além de um mesmo pacote de design tokens que garante a identidade visual do sistema nas duas plataformas. O aplicativo móvel, por sua vez, foi desenvolvido com Expo (SDK 58), React Native e Expo Router, com armazenamento seguro do token de acesso por `expo-secure-store`. A escolha do Expo se justifica por permitir produzir, a partir de uma única base de código TypeScript, um aplicativo para Android, plataforma de maior alcance entre os estudantes e alvo principal do trabalho, com possibilidade de execução em iOS, dispensando o desenvolvimento nativo separado e simplificando o ciclo de testes em emulador e em dispositivo físico, bem como a geração do arquivo de instalação (APK) distribuído junto ao trabalho. Em conjunto, as escolhas atendem ao objetivo de entregar um sistema de código aberto, reproduzível com poucos comandos e sustentável por um único desenvolvedor, conforme descrito na documentação oficial de cada uma das ferramentas citadas: NestJS, Prisma, PostgreSQL, React, Vite, Material UI e Expo.
